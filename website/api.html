API

The installed surface is one module, Ascon, holding four submodules. This page lists it in full; the generated odoc pages carry the same signatures with their documentation comments attached.

Ascon.Aead128

Authenticated encryption with associated data. Keys and nonces are abstract: the only way to build one is through a constructor that checks the length and copies the input. 

val key_size : int
val nonce_size : int
val tag_size : int

module Key : sig
  type t
  val of_bytes : bytes -> (t, [ `Invalid_length ]) result
  val of_string : string -> (t, [ `Invalid_length ]) result
end

module Nonce : sig
  type t
  val of_bytes : bytes -> (t, [ `Invalid_length ]) result
  val of_string : string -> (t, [ `Invalid_length ]) result
end

val encrypt :
  key:Key.t ->
  nonce:Nonce.t ->
  associated_data:bytes ->
  plaintext:bytes ->
  bytes * bytes

val decrypt :
  key:Key.t ->
  nonce:Nonce.t ->
  associated_data:bytes ->
  ciphertext:bytes ->
  tag:bytes ->
  (bytes, [ `Authentication_failure | `Invalid_tag_length ]) result

val encrypt_combined :
  key:Key.t ->
  nonce:Nonce.t ->
  associated_data:bytes ->
  plaintext:bytes ->
  bytes

val decrypt_combined :
  key:Key.t ->
  nonce:Nonce.t ->
  associated_data:bytes ->
  bytes ->
  (bytes, [ `Authentication_failure | `Invalid_tag_length ]) result
  • encrypt returns (ciphertext, tag) detached; the ciphertext has the same length as the plaintext.
  • encrypt_combined returns ciphertext || tag, which is 16 bytes longer than the plaintext.
  • decrypt_combined takes that blob positionally and rejects anything shorter than tag_size as `Invalid_tag_length.
  • associated_data is required, not optional. Pass Bytes.empty when there is none; an empty string and an absent one are the same input to the standard.
  • Both decrypt functions release plaintext only after the full tag verifies. There is no partial or streaming decrypt.

encrypt_combined raises Invalid_argument for the one case it cannot express: a plaintext within 16 bytes of Sys.max_string_length, where the combined result would not fit in a bytes. Every other failure in this module is a typed Error.

Ascon.Hash256

A fixed 256-bit hash with a persistent incremental context.

type ctx

val digest_size : int

val init : unit -> ctx
val feed : ctx -> bytes -> ctx
val feed_string : ctx -> string -> ctx
val get : ctx -> bytes

val digest : bytes -> bytes
val digest_string : string -> bytes
  • ctx is immutable: feed returns a new context and leaves its argument usable.
  • get does not consume or finalize the context, so a shared prefix can be extended more than once.
  • Nothing in this module can fail. There is no result anywhere in the signature.

Ascon.Xof128

The extendable-output function. The absorbing and squeezing phases are separate types, so the lifecycle is checked at compile time. 

type absorbing
type squeezing
type length_error = [ `Invalid_length ]

val init : unit -> absorbing
val absorb : absorbing -> bytes -> absorbing
val start_squeezing : absorbing -> squeezing

val squeeze :
  squeezing -> length:int -> (squeezing * bytes, length_error) result

val digest : bytes -> length:int -> (bytes, length_error) result
  • start_squeezing is one-way. Its result has type squeezing, which absorb does not accept.
  • squeeze returns the next state with its output, so successive calls continue the same stream. Their concatenation equals one longer squeeze.
  • A zero length to squeeze is a no-op returning empty output, not an error.
  • digest requires a positive length, as SP 800-232 does.

Ascon.Cxof128

The customized XOF. It differs from Xof128 in exactly one way: a customization string, processed before any message byte, that domain-separates the output. 

type absorbing
type squeezing
type error = [ `Customization_too_long | `Invalid_length ]

val init :
  customization:bytes -> (absorbing, [ `Customization_too_long ]) result

val absorb : absorbing -> bytes -> absorbing
val start_squeezing : absorbing -> squeezing

val squeeze :
  squeezing -> length:int -> (squeezing * bytes, [ `Invalid_length ]) result

val digest :
  customization:bytes ->
  message:bytes ->
  length:int ->
  (bytes, error) result
  • init rejects customization strings over 256 bytes and fully absorbs the accepted ones before returning, so the cost is paid once per context.
  • These absorbing and squeezing types are distinct from Xof128's. The two constructions cannot be mixed by accident.
  • Different customization strings give unrelated output for the same message. That is the point of the construction, and the tests assert it.

Error summary

Polymorphic variants used across the API
VariantWhere
`Invalid_lengthKey and nonce constructors; XOF and CXOF lengths
`Authentication_failureAead128.decrypt, Aead128.decrypt_combined
`Invalid_tag_lengthAead128.decrypt, Aead128.decrypt_combined
`Customization_too_longCxof128.init, Cxof128.digest

Each error set is written out per function rather than shared, so a match stays exhaustive without a catch-all case. See usage for what each one means in practice.

Deliberately not exported

The internal modules — the raw state, the permutation, the endianness helpers, the sponge, and the tag comparison — are built into the library but are not part of the installed API. They can change in a patch release.

  • The permutation. p[8] and p[12] are not callable. Building a new construction on them is not a supported use.
  • Tag truncation. Only 16-byte tags are produced or accepted.
  • Nonce masking. Not implemented.
  • Incremental AEAD. Not implemented, so that unauthenticated plaintext is never released.
  • Bit-level inputs. Every message argument is whole bytes; the API makes no arbitrary-bitstring claim.
